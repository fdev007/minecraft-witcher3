# bridge — мост этапа 1: Майнкрафт считает, Ведьмак показывает

Мост соединяет Fabric-мод MCW (`mc\`, TCP `127.0.0.1:25600`, JSON-строки) и The Witcher 3 (отладочный протокол
`-net`, exec-функции modMCW, `127.0.0.1:37001`). Мир блоков живёт в Майнкрафте. Мост показывает открытые блоки
вокруг Геральта как сущности Ведьмака (`mcw_batch`), переносит рельеф Ведьмака в Майнкрафт как `barrier`, водит
Геральта-`ServerPlayer` по позе из `mcw_poll` и превращает горячие клавиши в `act` (ломать и ставить решает Майнкрафт).
С этапов 3 и 5 мост ещё ведёт список крафта (`recipes`/`craft`, текст — `mcw_notify`) и показывает мобов
Майнкрафта плейсхолдерами (`ent` → `mcw_ents`).

Только stdlib, Python 3.12. Pip-пакетов нет, поэтому нет и `requirements.txt`. Тесты запускаются и через `unittest`,
pytest не обязателен. Сторона Ведьмака берётся из `..\spike\`: `w3net.py` (клиент протокола), `coords.py` (все
переводы координат и сборка `mcw_batch`), `templates.json`. Результаты прогона — в [SMOKE.md](SMOKE.md).

## Запуск

```powershell
python bridge.py                     # bridge.toml рядом: Ведьмак 127.0.0.1:37001, мод 127.0.0.1:25600
python bridge.py --w3-port 37101     # против фейковой игры: python ..\spike\fake_w3.py --port 37101
python bridge.py --check-keys        # клавиши конфига против input.settings Ведьмака (только чтение) и выход
python bridge.py --no-input -v       # без горячих клавиш, журнал DEBUG
```

Порядок запуска не важен: мост переподключается к обеим сторонам сам. Журнал пишется в `logs\bridge.log`
(ротация 5 МБ × 3) и в консоль. Раз в `log.metrics_every_s` (10 с) в журнал уходит строка метрик:

```
метрики: w3=synced mc=up мир=True | poll 15.0 Гц, RTT p50 8.6 p95 16.9 мс | в полёте 1 (batch 0), очередь batch 0 оп |
показано 32 / должно 32 | зеркало 34 бл., 81 чанков | рельеф 187 известно, 179 у мода, 1 ждут | ресинков 0
```

Если опрос держит меньше половины `poll.hz`, в строке будет пометка `(деградация)`.

Все настройки лежат в [bridge.toml](bridge.toml), у каждой есть комментарий, значения по умолчанию — в `config.py`.
Неизвестный ключ в файле считается ошибкой. Флаги CLI перекрывают файл: `--w3-host/--w3-port`, `--mc-host/--mc-port`,
`--log`, `--metrics`, `--no-input`, `--config`.

## Горячие клавиши

Клавиши работают, только когда на переднем плане окно процесса `witcher3.exe`: мост опрашивает `GetAsyncKeyState`
через ctypes с частотой 100 Гц. В игру и в окна мост ничего не шлёт и фокус не трогает. Действие срабатывает в
момент нажатия, автоповтора нет. Если клавишу зажали в другом окне и потом переключились в игру, она не сработает.

| Действие | Клавиши | Что делает |
|---|---|---|
| `toggle` | **F2** | Режим строительства. Пока он выключен, остальные клавиши моста ничего не делают |
| `break` | **Mouse4** (задняя боковая), **8** | Ломает блок под прицелом камеры |
| `place` | **Mouse5** (передняя боковая), **9** | Ставит блок из выбранного слота |
| `slot1`…`slot9` | **NumPad1…NumPad9** (NumLock должен быть включён) | Выбирает слот хотбара |
| `slot_prev` / `slot_next` | **[** / **]** | Предыдущий или следующий слот (для клавиатур без цифрового блока) |
| `craft_menu` | **F3** | Список крафта: открыть или закрыть |
| `craft_prev` / `craft_next` | **PageUp** / **PageDown**, **NumPad −** / **NumPad +** | Листать список |
| `craft_do` | **0**, **NumPad0** | Скрафтить выбранное один раз |
| `fp` | **F4** | Вид от первого лица: вкл/выкл. Работает и вне режима строительства. Взгляд — мышью внутри игры (`mcw_steve.ws`), тело Геральта скрыто, ставить и ломать — по центру экрана ([STEVE.md](../docs/STEVE.md)) |
| `inventory` | **E** | Режим Стива: есть подсказка взаимодействия Ведьмака (`mcwf_interact`) — E остаётся ему (дверь, NPC, лут), нет — инвентарь MC; экран MC открыт — закрыть. Вне режима Стива — только Ведьмаку |
| `horse` | **X** | Режим Стива: лошадь MC к Геральту (`horse{}` моду). Вне режима — Плотва Ведьмака |
| `summon` | **F6** | Тест: призвать `ents.summon_type` (крипер) в `ents.summon_dist_m` (6 м) перед Геральтом |

Почему такие клавиши. `Documents\The Witcher 3\input.settings` (110 989 Б, читали только на чтение) и шаблон
`bin\config\r4game\legacy\base\input_qwerty.ini` в контекстах Exploration, Combat, Horse, Swimming, Boat и BASE_*
занимают:

- все 26 букв (W/A/S/D, E — взаимодействие, Q/R/F/T/Y — знаки и зелья, Z/X/C/V, H…P — панели);
- цифры **1–7**: мечи, масла, знаки;
- Space (прыжок, кувырок), LShift (бег), Alt (уклонение), CapsLock (шаг), Tab (радиальное меню), Enter, Esc,
  Backspace, Home (HUD);
- кнопки мыши: левая — атака, правая — блок и фокус, средняя — бросок предмета и медитация, колесо (`IK_MouseZ`) —
  смена знака;
- F1 — подсказка, F5 — `ShowDeveloperMode`.

Мимо `input.settings` игра держит ещё несколько клавиш: F5 — быстрое сохранение (`igmOptions.ws:1522`,
`permaLocked`), F9 — быструю загрузку, F7 — RT (только в не-final сборке). F8 дописывает мод 13072 (первое лицо),
F12 — скриншот Steam, `~` — консоль. Поэтому ломать и ставить нельзя ни на кнопки мыши (как в Майнкрафте), ни на
цифры 1–9.

Свободны боковые кнопки мыши (`IK_Mouse4`/`IK_Mouse5` в exe есть, нигде не привязаны), цифры **8, 9, 0**, F2/F3/F4/F6,
скобки, Insert/Delete/PageUp/PageDown/End и цифровой блок. Из цифрового блока заняты только NumPad1/2/4
(`Debug_KillAllEnemies`, `Debug_KillTarget`, `Debug_TeleportToPin`), но их слушатели ваниль регистрирует лишь в
не-final сборке (`game\player\playerInput.ws:173-182`, обработчики ещё и проверяют `IsFinalBuild`, `:3555+`).
В розничной игре эти клавиши ничего не делают.

Клавиши этапов 3 и 5 сверены так же, через `hotkeys.bound_keys` по `input.settings` (3 065 строк, только чтение):
у F3, F6, PageUp, PageDown, NumPad −, NumPad +, 0 и NumPad0 привязок нет ни в одном контексте, в жёстких клавишах
их тоже нет. В шаблоне `input_qwerty.ini` их нет, в скриптах ваниль упоминает только PageUp/PageDown — как иконки
листания страниц в меню (`game\localizedContent.ws:877-878`). В меню игры они листают страницы панели, но клавиши
моста там и так обычно не нужны.

`python bridge.py --check-keys` сверяет клавиши конфига с `input.settings` и со списком жёстких клавиш, Debug_* при
этом пропускает. На этой машине конфликтов нет. При старте моста та же проверка пишет предупреждение в журнал. Имена
клавиш в конфиге — из `hotkeys.VK`: буквы, цифры, `F1`…`F24`, `NUMPAD0`…`NUMPAD9`, `MOUSE4`, `MOUSE5`, `LBRACKET`,
`INSERT`…, а также `0x..`. На AZERTY и QWERTZ цифры и скобки стоят на других физических клавишах; в этом случае
проверьте `--check-keys` и при необходимости поправьте `[input.bind]`.

## Как устроено

```
Fabric-мод (mc\)  ◄─ JSON-строки ─►  bridge.py  ◄─ exec / ответы [MCW#seq] ─►  Witcher 3 (modMCW)
                                     │ главный поток: очередь событий, все решения
                                     ├ поток чтения мода, поток чтения w3net, потоки подключения
                                     └ поток опроса клавиш
```

Состояние меняет только главный поток. Остальные потоки кладут события в очередь, у каждого события есть номер
поколения соединения: после переподключения события старого соединения выбрасываются. Подключение идёт в
отдельном потоке, потому что на Windows отказ на localhost приходит только через ~2 с. Ссылок на сущности Ведьмака
мост не держит.

| Файл | Что |
|---|---|
| `bridge.py` | главный цикл, решения, CLI |
| `world.py` | зеркало по чанкам, отбор открытых блоков, дифф «показано ↔ должно быть», нарезка `mcw_batch`, цель по `mcw_look` |
| `ground.py` | рельеф: вопросы `mcw_ground`, кеш, `ground` / `ground_clear` |
| `hotkeys.py` | `GetAsyncKeyState`, окно `witcher3.exe`, проверка конфликтов с `input.settings` |
| `mobs.py` | мобы из потока `ent`: таблица, отбор и слоты плейсхолдеров, операции `mcw_ents` |
| `craft.py` | список крафта из `recipes`, курсор, текст для `mcw_notify` |
| `links.py` | соединения с модом и с игрой (поверх `spike\w3net.W3Client`) |
| `config.py`, `bridge.toml` | настройки |
| `test_bridge.py` | тесты без игры и без сервера (fake_w3 + фейковый мод) |
| `smoke_bridge.py` | сквозной прогон с настоящим Fabric-сервером (итог — [SMOKE.md](SMOKE.md)) |
| `smoke_stage35.py` | то же для этапов 3 и 5: дерево → доски → верстак → кирка, крипер (итог — [SMOKE.md](SMOKE.md)) |

### Опрос Ведьмака
Мост держит конвейер `mcw_poll(seq)`: `poll.hz` (15) раз в секунду, не больше `poll.depth` (2) запросов в полёте.
Запросы идут по расписанию, а не «через 1/hz после прошлого», иначе шаг цикла съедал бы частоту. Если игра отвечает
медленнее, конвейер заполняется и частота падает до `depth / RTT` сама. Всего в полёте не больше `w3.max_inflight`
(8) exec любого вида. По `pos`/`cam` мост шлёт моду `pos{p, yaw, pitch}`: позицию и курс Геральта, наклон — по
камере. Шлёт при изменении и не реже `pos_keepalive_s`, сразу — после `pteleport` и `respawn`. Координаты считает
только `spike\coords.py`.

При деградации первым ждёт рельеф: если последний ответ опроса пришёл дольше `ground.pause_rtt_ms` (250 мс) или
опрос висит дольше этого, новых `mcw_ground` нет. Опрос и пакеты блоков идут как обычно.

### Пересинхронизация
Новое соединение с игрой (мост запустили или переподключился) — `mcw_clearall`. После ответа запись «что
показано» пуста, и дифф ставит всё заново. То же происходит, когда:

- в `mcw_poll` сменились `world` или `area`. Дополнительно рельеф забывается, у мода снимается весь свой barrier
  (`ground_clear` без box), рельеф спрашивается заново;
- число блоков в игре расходится с записью. Проверка идёт раз в `resync.count_every_s` (2 с) и сразу после
  возвращения в мир. Главный случай — загрузка сейва: сущности `PM_DontPersist` исчезают, счётчик = 0. Мост
  спрашивает `mcw_countblocks` (блоки без проб `MCW_TEST`) и ждёт ровно «показано». Если мод старый и отвечает
  `Warn: Failed to process command`, мост до конца соединения переходит на `mcw_count`. Тот считает и бочки
  `mcw_boom` (у них тоже `MCW_BLOCK`), поэтому допуск — от «показано» до «показано + бочки»;
- пакет `mcw_batch` потерян или просрочен: что стоит в игре, неизвестно, ресинк обязателен.

Ресинк по расхождению не чаще `min_interval_s` (5 с). Если ресинки идут подряд, интервал удваивается до
`max_interval_s` (60 с): если что-то в игре не ставится, мост не будет долбить её пересозданием 2000 сущностей.
Пакеты и счётчики, отправленные до последнего `mcw_clearall`, на решения не влияют (номер эпохи).

Обрыв мода показ замораживает: сущности в Ведьмаке остаются, пока не придёт новый снапшот. После переподключения
мост шлёт новый `hello`, зеркало строится заново, и дифф трогает только то, что изменилось.

### Что показывать
Зеркало хранится по чанкам и строится из `chunk`, `blocks` и `unchunk`, как `mc\fake_bridge.Mirror`. В Ведьмаке
показываются блоки, которые одновременно:

- не воздух (его в протоколе нет), не `barrier` и не из `display.hide` (вода, лава, огонь…);
- с хотя бы одной открытой гранью. Грань закрыта непрозрачным соседом из зеркала (`display.transparent` — стекло,
  листва, двери… не закрывают) или рельефом Ведьмака: сосед ниже верха известной колонны;
- не дальше `display.radius_m` (32 м) от Геральта до центра блока;
- не больше `display.max_entities` (2000), ближние первыми.

Список открытых блоков кешируется по чанкам и пересчитывается, когда меняется сам чанк, блок на границе соседа
или верх колонны рельефа.

### Дифф и пакеты
`Display.shown` — запись моста: клетка → (шаблон, готовая команда `clear`). `clear` строится тем же шаблоном и
`coords.clear_op`, что и `set`, поэтому origin совпадает до сантиметра. Дифф выдаёт сначала все `clear`, потом
`set`, ближние первыми. Замена блока — это `clear` + `set`: `set` в занятую клетку дал бы в Ведьмаке дубль
сущности. Внутри пакета мод тоже сначала выполняет все `clear`, поэтому `clear` и `set` одной клетки могут
оказаться в одном пакете.

Команды режутся по байтам UTF-8 не длиннее `batch.bytes` (1900; жёсткий потолок 2047 — замер на 5.00c: команду
длиннее игра молча выбрасывает, ответа нет), в полёте не больше `batch.inflight` (2) пакетов. Запись обновляется в момент отправки: игра исполняет exec по порядку.
Шаблон — `display.default_template` (0, cont_crate). Таблица имя блока → индекс — `[display.templates]`.

### Рельеф → barrier
Для колонн в радиусе `ground.radius_m` (24 м, 1 793 колонны), ближних первыми, мост спрашивает `mcw_ground(seq, x, y)`
в центре колонны. Ограничения: не чаще `rate_hz` (40/с), не больше `inflight` (4) в полёте. Ответы кешируются по
колонне. Колонна без опоры (`ground 0 0`) переспрашивается через `retry_none_s`. Верх barrier = `round(h) − 1`,
считается через `coords.cm_to_block` от `h + 0,5 м`: блок, поставленный на землю, утоплен или висит не больше чем
на 0,5 м. Колонна уходит вниз на `depth` (3) блоков.

Моду рельеф уходит пачками `ground{c}` раз в `send_interval_s`. Колонны из `ground_ok.skip` (чанк не загружен)
ждут своего `chunk`. Чанки, от которых Геральт ушёл дальше `clear_dist_m` (96 м), снимаются `ground_clear{box}`.
Песок, лежащий на снятом barrier, упадёт в пустоту; `clear_dist_m = 0` отключает снятие. Если Геральт вернётся,
высоты возьмутся из кеша без новых вопросов игре. Кеш дальше `2 × clear_dist_m` забывается.

### Ввод и действия
`break`/`place` → `mcw_look(seq)` → клетка и грань → `act{id, a, b, face, hit, slot, p, yaw, pitch}` с позой и
взглядом камеры на момент нажатия.

Новый мод отдаёт после `look` строку `normal nx ny nz` (×10000, `SRaycastHitResult.normal`). Мост её проверяет:
длина 0,5–1,5, нормаль смотрит на камеру. Если проверка прошла, грань — это ось нормали. Клетка своего блока берётся
на 5 см внутрь поверхности, клетка перед стеной — на 5 см наружу; землю под barrier мост признаёт, только если
нормаль смотрит вверх. В журнале у `act` пишется «нормаль: из игры». Если строки нет (старый мод) или она не
прошла проверку, мост выводит грань сам:

- **свой блок** (`isBlock = 1`): из показанных клеток рядом с точкой попадания выбирается та, в которую луч в этой
  точке входит и чей центр ближе всего по Чебышёву (ящик ~1,03 м, pivot сдвинут на 3,6 см, соседние ящики
  перекрываются на 1,5 см). Грань — ось наибольшего смещения точки от центра;
- **рельеф** (`isBlock = 0`): если верх barrier колонны известен и точка рядом с ним (±1 м), это клик по этому
  barrier гранью `up`, и Майнкрафт поставит блок на свою землю. Иначе (стена, рельеф ещё не спрошен) — клетка
  перед поверхностью, грань к камере. Ломать рельеф нечего: игроку уйдёт «nothing to break there».

`ack ok:false` превращается в `mcw_notify` («MCW: cannot place: too far»). Остальные уведомления: выбор слота
(«slot 3 - dirt x8»), режим строительства, урон («HP 14/20»), изменения инвентаря с накоплением за `inv_window_s`
(«+1 dirt, -2 oak_planks»), смерть и возрождение. Сообщения идут не чаще `notify.min_interval_s`, одно сообщение
каждого рода в очереди. Текст — латиница, кириллица, цифры и `.,:;!?+-_/()%#=`, остальное заменяется на `?`, не
длиннее 120 байт UTF-8. Причина — charset-замер на 5.00c: кавычка `"` или `'` внутри строкового аргумента exec ломает
разбор всей команды, экранирования нет (`\` доходит как есть), пустую строку `""` игра тоже не разбирает — пустое
уведомление не шлётся вовсе. Пустые `mcw_batch`/`mcw_ents` не собираются (`coords.batch_call`/`ents_call` бросают
`ValueError`); аргумент, который `w3net.fmt_arg` не пропустит, мост не шлёт и считает в `refused_<род>`.

`explosion` в пределах `boom.radius_m` (48 м) от Геральта вызывает `mcw_boomat(seq, x, y, z)` не чаще раза в
секунду. Точка — центр взрыва в мировых см Ведьмака (`coords.mc_pos_to_w`); мод ставит бочку на опору под ней и
взрывает с запалом 0,2 с. Старый мод отвечает `Warn: Failed to process command` — тогда мост повторяет взрыв через
`mcw_boom(seq)` (бочка в 4 м перед Геральтом) и дальше пользуется им. Снесённые блоки придут обычным `blocks`.

### Слот и крафт (этап 3)
Инвентарь живёт на сервере, мост только повторяет `inv`. Слот хотбара выбирает сервер: клавиша слота шлёт
`act select`, номер мост ставит сразу, подтверждение — `inv.sel` того же тика (его мост и принимает за правду,
например после переподключения). Без связи с модом слот не меняется, а в игре появляется «Minecraft is offline».
`break` и `place` несут в `act` свой `slot`.

Список крафта:

- F3 шлёт `recipes`, ответ мода — рецепты, которые можно скрафтить из инвентаря. Строка в игре:
  `MCW craft 2/7: oak_planks x4, can 3`; у рецептов 3×3 — `(table)` или `(needs table)`.
- PageUp/PageDown листают. После любого изменения инвентаря при открытом списке мост перезапрашивает его (не чаще
  раза в 0,5 с), курсор остаётся на том же рецепте.
- 0 шлёт `craft{recipe, n:1}`. Итог — отдельной строкой: `MCW: crafted 4 oak_planks` или
  `MCW: cannot craft wooden_pickaxe: needs a crafting table in reach`. У итога свой род уведомления, поэтому
  листание его не вытесняет.

Верстак мод ищет сам, в досягаемости Геральта. Чтобы им пользоваться, верстак ставят обычным `place`.

### Мобы (этап 5)
Мод шлёт поток `ent` (дельты: `spawn`, `move`, `hp`, `fuse`, `item`, `remove`); `mobs.EntTable` держит последнее
состояние каждой сущности. `mobs.EntDisplay` выбирает, кого показать: мобов с шаблоном (`[ents.templates]`, иначе
`default_template`, −1 — не показывать) не дальше `ents.radius_m`, не больше `ents.max`, ближних первыми.
Предметы на земле плейсхолдеров не получают: вместо них счётчик в `mcw_notify` (`MCW: on the ground: 3 oak_log`),
когда предметов в `items_radius_m` становится больше.

Пакет `mcw_ents(seq, "spawn:id:x:y:z:yaw:t|move:id:x:y:z:yaw|kill:id|wipe")` идёт не чаще `ents.hz` (10/с), в
полёте один. `id` — слот моста 0..63, у мода это тег `MCW_E<id>` (имя из числа WitcherScript строит только switch
по литералам, как ваниль). Освобождённый слот уходит в конец очереди, поэтому `kill` и `spawn` одного слота в одном
пакете не встречаются. Origin плейсхолдера — низ bbox шаблона на уровне ног моба, центр по горизонтали над ними
(`coords.ent_origin_w`); курс — `coords.mc_yaw_to_w`. Запись «что показано» меняется при отправке, как у блоков.
Сбой пакета, ошибки в ответе (move или kill пустого слота: например, загрузили сейв) и каждый `mcw_clearall` дают
`wipe` (снести все `MCW_ENT`) и всех заново; `spawn` у мода идемпотентен по слоту. Старый мод без `mcw_ents` мост
узнаёт по `Warn: Failed to process command` и больше её не шлёт: блоки работают как раньше.

Крипер зашипел (`fuse 1`) — `MCW: creeper is hissing!`. Взрыв идёт прежним путём: `explosion` → `mcw_boomat` в
точке, снесённое — `blocks`, урон — `hp` (`MCW: HP 10.9/20`).

**Плейсхолдер крипера — `cont_crate` (t = 0), а не бочка.** cont_crate — голый `CEntity` без геймплея: игнис,
меч и бомбы с ним ничего не делают. bbox и pivot известны (центр, 1,03 м), поэтому ящик ставится ровно на ноги
моба, и этот шаблон уже проверен блоками. Бочка (`COilBarrelEntity`) взрывается от огня: игнис Геральта устроил бы
в Ведьмаке взрыв, которого нет в Майнкрафте. Визуал бочки — APEX-разрушаемый `CDestructionSystemComponent`, bbox
не снят, а на физику при телепорте 10 раз в секунду лучше не рассчитывать. Бочка остаётся эффектом взрыва
(`mcw_boomat`). Минус ящика — он похож на блок; отличает его движение и уведомление о шипении. Свой вид крипера
будет из REDkit, шаблон меняется строкой в `[ents.templates]`.

**Плавность.** Каждый `move` у мода — `TeleportWithRotation` (`engine\entity.ws:47`; на `CEntity` так зовёт
ваниль: `btTaskBruxaSpawn.ws:109`), то есть ящик прыгает с частотой `ents.hz`. На смоуке крипер прошёл 3 м за
12 `move`. Лучше для `CEntity` в скриптах 5.00c ничего нет. `SetRawPlacement` (`entity.ws:91`, новое в 5.0) в
ванили не вызывается ни разу — **[проверить]**, дешевле ли он. Плавное движение есть у `CActor`, и его неблокирующие
варианты можно звать из exec: `ActionSlideToWithHeadingAsync(target, heading, duration)` (`game\actor.ws:814`,
ваниль: `btTaskDodge.ws:558`), `ActionSlideToAsync` (`:804`), `ActionMoveToAsync` (`:777`,
`btHorseRidingManager.ws:520`). Латентные `ActionMoveTo` и `ActionSlideTo` из exec не вызвать. Когда в REDkit
появится свой моб-актёр (`CNewNPC` с внешностью крипера), `move` станет `ActionSlideToWithHeadingAsync` с
`duration = 1 / ents.hz`: движок сам дотянет между апдейтами.

**Ящик моба в лучах Ведьмака.** У плейсхолдера нет `MCW_BLOCK`, поэтому `mcw_ground` его не пропускает и мог бы
принять верх ящика за землю. Мост помечает вопрос рельефа, если в момент отправки над колонной стоял моб (игра
исполняет exec по порядку), и такой ответ не принимает: колонна спрашивается снова через 2 с
(`ground_mob_blocked` в статистике). Если `mcw_look` упёрся в ящик моба, мост ничего не ломает и не ставит:
`MCW: place: creeper in the way`.

**Урон по мобу из Ведьмака (на будущее, не сделано).** Геральт бьёт мечом плейсхолдер — у `CEntity` это никаких
событий не даёт. Вариант: моб — свой класс из REDkit на основе `CNewNPC`/`CActor` с обёрткой события получения
урона (`OnTakeDamage`/`ReactToBeingHit` через `@wrapMethod` или в своём классе). Обработчик кладёт `(слот, урон)`
в поле `@addField(CR4Player)` (очередь — та же техника, что токен сессии в modMCWProbe), `mcw_poll` печатает
строки `hit <id> <урон>` и очищает очередь. Мост превращает их в новое сообщение моду `attack{ent}`, а мод зовёт
`GeraltPlayer.attack(entity)` предметом в руке. Тогда урон, отбрасывание, смерть и дроп считает Майнкрафт, и они
вернутся обычным `ent`. Пока Ведьмак может только показать, что Геральт попал по мобу.

### Клиент Майнкрафта и режим Стива (`client.py`)
Скрытый клиент (`..\mcclient`, протокол — его README) мост ищет на `client.port` (25601) и переподключается сам,
как к остальным сторонам. Отключить — `[client] enabled = false`, тогда всё как раньше.

- **Поза.** Вне режима Стива из каждого `mcw_poll` клиент получает `pose{p, yaw, pitch}`: ноги Геральта в
  координатах MC и взгляд камеры Ведьмака (`Pose.look_angles`). Клиент стоит там же и смотрит туда же, поэтому его луч
  прицела — центр экрана Ведьмака. `pos` серверному моду идёт как раньше: для игрока клиента сервер берёт из него
  только прыжки дальше 8 блоков (быстрое перемещение Ведьмака).
- **Ходит клиент** (`client.drive`, в режиме Стива): клиенту `follow{on:false}`, клавиши `[client.pass_drive]` (WASD,
  пробел, левые Shift и Ctrl), Ведьмаку `mcwf_block(2)` (бой и движение Геральта) и `mcwf_on(1, 1, sens)` (глаз камеры
  — от клиента). Каждый `eye` клиента (не больше одного `mcwf_mc` в полёте) мост переводит в мировые см Ведьмака:
  глаз, скорость `(vx, −vz, vy)`, высота глаза. Камера встаёт в глаз, Геральт-кукла — в ноги, ответный взгляд
  Ведьмака уходит клиенту `look` (курс MC = 180 − курс W3, наклон MC = −наклон W3). Если ноги MC больше чем на 2 м ниже
  известной земли колонны (`eye_below_ground` в статистике), `mcwf_mc` не шлётся: камера и кукла не уходят за
  провалившимся игроком под мир.
- **FOV.** При включении режима мост спрашивает FOV камеры Ведьмака (`mcwf_fov`, `fp.fov` > 0 — сначала поставить) и
  шлёт клиенту вертикальный FOV мира (`client.fov_axis = "v"`: у `poster_camera.w2ent` FOV вертикальный). Рамка блока MC
  тогда ложится на блок Ведьмака.
- **Земля** (`_step_terrain`, раз в 50 мс): известные высоты колонн (`GroundPlanner.height`, тот же `mcw_ground`, что
  для barrier) — клиенту `terrain{c:[x, z, h_cm, ...]}`, ближние к Геральту первыми, по 512. Новый клиент или другой мир
  Ведьмака — `terrain{reset}` и всё заново. По ним ходит физика клиента; `ground.rate_hz` поднят до 80: колонны должны
  успевать впереди идущего игрока.
- **Дома, стены, полы** (`solid.py`, `_step_solid`, пока включён вид от первого лица): колонны в радиусе
  `solid.radius_m` от ног игрока MC, ближние и те, что по ходу (скорость × 0,4 с), первыми — у игры `mcw_cols`
  (`mcw_collide.ws`), до `per_call` за вызов. Игра отвечает на колонну строкой: без статики — высота земли (только
  Terrain, без крыш), со статикой — 16 подколонн с твёрдыми промежутками. Не влезшие в ответ (до 1999 байт) — «stop»,
  они снова в очереди. Переспрашивает, если игрок ушёл по высоте дальше `rescan_dz_m` (окно ответа: ноги −8…+12 м), и
  колонны с дверью ближе `door_radius_m` — каждые `door_every_s`. Клиенту — `solid{c}` (новые и изменившиеся). Земля
  для `eye_below_ground` — тоже отсюда (иначе в доме под крышей мост считал бы игрока провалившимся).
- **Пауза Ведьмака** (`_step_w3pause`, 2 раза в секунду `mcw_state`): на паузе, в меню, в сцене, не в мире или без
  связи с игрой сервер MC стоит — `cmd tick freeze`, снова играем — `tick unfreeze` (`mc.freeze_on_pause`; шлётся только
  смена, после переподключения к серверу — заново).
- **Сторож процессов** (`supervise.py`, `[supervise]`): связи с сервером MC нет дольше `server_down_s` —
  `mc\run_server.ps1 -Stop` и запуск; клиент не на связи или не в мире дольше `client_down_s` при живом сервере —
  `mcclient\run_client.ps1 -Stop` и запуск. В своём потоке, не чаще `min_interval_s`. По умолчанию в коде выключен
  (тесты и смоуки не трогают настоящие процессы), включает `bridge.toml`.
- **Модели MC** (`mcw_models.ws`, мод `modMCWModels`). Тело Стива: раз в 5 с `mcwm_skin(1)` (идемпотентно: после
  загрузки сейва Геральт новый — надевается снова; «skin 0 0» — шаблонов нет, переспрос раз в 30 с). Лошади: `horses`
  клиента (кадр) -> `mcwm_horse` на каждую, слот 0..3 по id сущности MC, курс W3 = 180 − курс MC (под всадником —
  ноги от глаза игрока, flags 8: Ведьмак ставит её от глаза своей камеры; без всадника — на землю колонны, если та в
  пределах 0,6 м от barrier-высоты сервера, `_horse_ground`); лошадь пропала —
  слот прячется (flags 0). X в режиме Стива -> моду `horse{}` (лошадь к Геральту), вне режима — Плотва Ведьмака; с
  `input.settings` X конфликтует намеренно (`own_keys`). Ящик-плейсхолдер у `minecraft:horse` выключен
  (`ents.templates` = −1).
- **Режим Стива** = вид от первого лица (F4) + Ведьмак в мире + клиент в мире. Тогда:
  - кнопки `[client.pass]` (по умолчанию ЛКМ, ПКМ, СКМ) уходят клиенту нажатием и отпусканием. Опрос
    `GetAsyncKeyState` — свой поток, как у горячих клавиш (`hotkeys.Passthrough`). Нажатие засчитывается только
    фронтом в окне Ведьмака; ушёл фокус — всё отпускается;
  - слоты (`slotN`, `slot_prev/next`) идут клиенту клавишами 1–9 и колесом, без режима строительства; цифры 1–9 и Q —
    тоже в `[client.pass]` (у Ведьмака на 1/2 мечи, на Q знак — в режиме Стива они заблокированы `mcwf_block`);
  - колесо и сдвиги мыши читает `rawmouse.RawMouse` (Raw Input, `RIDEV_INPUTSINK` на своём окне сообщений: приходит,
    когда на переднем плане Ведьмак; `GetAsyncKeyState` колесо не видит). Колесо — клиенту `scroll`; пока у клиента
    открыт экран (`state.screen`), сдвиги — `cursor` (`client.cursor_scale`), а Ведьмаку `mcwf_freeze(1)`: взгляд стоит;
  - E (`input.bind.inventory`): экран MC открыт — E клиенту (закрыть); иначе `mcwf_interact`: у Ведьмака есть подсказка
    взаимодействия (дверь, NPC, лут) — E остаётся ему, нет — E клиенту (инвентарь MC). С `input.settings` E конфликтует
    намеренно, в сверке конфликтов не участвует (`own_keys`);
  - ломать, ставить и крафтить горячими клавишами (`break`, `place`, `craft_*`) в режиме Стива мост не делает — это ЛКМ,
    ПКМ и инвентарь самого MC;
  - 4 раза в секунду `mcwf_state`: восьмое поле — идёт сцена (диалог, катсцена, лошадь). На сцену режим Стива гаснет
    (`w3_susp`), после — возвращается сам;
  - оверлей показывает картинку клиента (`mode 1`), Ведьмаку — `mcwf_block(1)`: Геральт не бьёт, не включает
    чутьё и не бросает.

  Режим погас — клиенту `release`, оверлею `mode 0`, Ведьмаку `mcwf_block(0)`. Мост перезапустился, а вид от первого
  лица в игре уже включён: мост узнаёт это по `mcwf_state`, блокировку шлёт только после ответа.
- **Оверлей** (`client.overlay`, по умолчанию `..\overlay\mcw_overlay.exe`) — дочерний процесс, пока клиент на связи.
  Вышел — перезапуск через 5 с. Мост закрылся — у оверлея закрывается stdin, и он выходит сам. Вывод оверлея — в
  журнал моста.
- **Подмена Геральта на сервере** приходит сообщением `geralt{client}` (журнал «Геральт теперь игрок клиента MC»).
  Пока Геральт меняется, мод на `pos` и `ground` отвечает `error no_geralt`, это 1–2 тика.

### Бой и стрелы (`combat.py`, `[combat]`, `[arrows]`)

Только в режиме Стива, пока ходит клиент MC. Раз в `1/combat.hz` — `mcw_npcs(r, max)`: NPC Ведьмака вокруг (строки
`n`) и удары NPC по Геральту с прошлого вызова (строки `h`, доля его жизненной силы). NPC уходят серверу
`npcs{l}` (там — невидимые прокси, `mc/.../Npcs.java`), удары — `phurt{id, dmg}`, где `dmg = доля x 20 x hurt_mult`
(слабее `min_hurt` — не шлём). Вышли из режима — `npcs{l: []}` один раз, прокси убраны. Удар клиента MC по прокси
приходит от мода `npc_hit{id, dmg, kind, crit}` -> `mcw_npchit(id, доля x 10000, heavy, ranged, сила x 1000)`: Ведьмак
бьёт ударом Геральта его мечом, умноженным на силу `dmg / ref_mc_dmg` (6 — полный удар железным мечом); доля
`dmg / npc_mc_hp` — только если меча у Геральта нет; тяжёлая реакция — крит или `dmg >= heavy_dmg`. Мод без `mcw_combat.ws` отвечает «Failed to
process» — бой выключается до переподключения.

Позиции NPC мост снимает до 30 раз в секунду, скорость считает по двум снимкам (время — движка Ведьмака, строка `t`),
шлёт серверу (прокси двигаются по скорости в начале каждого тика) и клиенту напрямую (`npcs` по карте `npc_map`:
клиент ставит прокси перед каждым выбором цели). Ближний удар — сначала `mcw_npcwarn` (начало замаха), сам удар —
через `impact_delay_s`: NPC успевает парировать или отскочить; ответ `npchit` с флагами парирования и уклонения ->
серверу `npc_block` (отдача игроку). Щит клиента (`block` в `state`) -> `mcwf_guard`: удары NPC спереди Ведьмак
парирует. Стены для стрел: `arrow_path` мода -> `mcw_path` -> `arrow_wall`.

Стрелы: клиент шлёт `arrows{a}` каждый кадр; `ArrowSlots` раздаёт 8 слотов пула стрел Ведьмака, воткнувшуюся и
неподвижную повторно не шлёт, пропавшую прячет (`<слот>:off`). Первым делом на подключение — `mcwa_arrows("init")`:
пул создаётся заранее, иначе первые стрелы растворялись бы, как новые блоки.

## Ограничения этапа 1 и что проверить на настоящей игре

- **Log() в ответе exec.** Если на 5.00c вывод `Log()` не приходит в ответе, все ответы будут «тихими», и мост не
  увидит ни позы, ни подтверждений. Запасной канал — `w3.scriptslog = "auto"` (хвост `scriptslog.txt`, игра с
  `-debugscripts`).
- **Темп канала.** Сколько exec игра исполняет за кадр, неизвестно. Рельеф радиуса 24 м — это 1 793 вызова; на
  фейке при 40/с он заполняется за 45 с. Если exec — один за кадр, сумма опроса (15), рельефа (40) и пакетов
  упрётся в FPS. Тогда снизить `ground.rate_hz` или `ground.radius_m` и смотреть метрики.
- **Размер пакета.** `mcw_batch` разбирает строку через `StrSplit` за O(len²). Размер — 1900 байт (~70 операций),
  выше 2047 игра команду не исполняет; меньше — подобрать по `batch` ms из ответа (в журнале на DEBUG) и по FPS.
- **Грань по лучу.** Попадание в свой ящик (`isBlock`), группы коллизий луча и pivot `cont_crate` на живой игре не
  проверены. Не проверено и то, что `SRaycastHitResult.normal` мировая и единичная: в фейке это так по
  построению. Если break/place промахиваются на клетку, первым делом смотреть `act … грань … нормаль …` в журнале.
- **Высота опоры.** Как `mcw_ground` ведёт себя на склонах, мостах и в домах (колонна уходит на крышу), не
  проверено. Верх barrier — по центру колонны.
- **Мир и сейвы.** Смена мира пока одна на весь Майнкрафт: Велен и Скеллиге делят одно измерение, рельеф при смене
  снимается и строится заново. Отдельные `dimension_type` на мир Ведьмака — после спайка. Загрузку сейва мост
  ловит по нулевому счётчику блоков с задержкой до `count_every_s`.
- **Пауза, меню, катсцены.** Пока в ответе нет `pos`, пакеты не шлются, рельеф не спрашивается, клавиши не
  действуют. Что отвечает `mcw_poll` в катсцене и на загрузке, не проверено.
- **Взрыв.** Вживую не проверены запал 0,2 с у `mcw_boomat` и опора лучом от +1 до −5 м: бочка может встать на
  ящик-блок над точкой взрыва, если он ниже 1 м.
- **Время копания.** В выживании ломка блока занимает время по правилам Майнкрафта (земля рукой — 0,75 с), ack
  приходит после.
- **Клавиши.** NumPad-слоты работают только при включённом NumLock. На раскладках, отличных от QWERTY, нужно
  проверить `--check-keys`.
- **Мобы (этап 5).** На игре не проверены: `GetEntityByTag` по тегу слота и видит ли он сущность, созданную или
  уничтоженную в том же кадре; как выглядит `TeleportWithRotation` ящика 10 раз в секунду и тянется ли за ним
  коллизия статического меша; направление курса `EulerAngles(0, yaw, 0)`; попадает ли ящик моба в лучи
  `mcw_ground`/`mcw_look` (мост и так страхуется); стримится ли меш `cont_crate` у движущейся сущности
  (`streamingDistance 10`).
- **Крафт (этап 3).** Список и итог видны только через `ShowNotification`: длинный список листается по одной
  строке. Уведомления идут не чаще `notify.min_interval_s`, и при очень частых нажатиях промежуточные строки
  списка заменяются следующими. Итог крафта не теряется: у него свой род.

## Контракт мода для моста

Расширения добавлены в `spike\mod\modMCW\content\scripts\local\mcw_spike.ws` и повторены в `spike\fake_w3.py`.
Только добавления: прежние сигнатуры и строки вывода не менялись.

- `mcw_countblocks(seq)` → `countblocks <блоки> <пробы>`. Блоки = `MCW_BLOCK` минус `MCW_TEST`: два нативных списка,
  без обхода сущностей в скрипте.
- `mcw_look(seq)` при попадании печатает ещё строку `normal <nx> <ny> <nz>` (×10000).
- `mcw_boomat(seq, x, y, z)` → `boom <ok>`: бочка в точке (мировые см) на опоре под ней, запал 0,2 с.
- `mcw_ents(seq, "spawn:id:x:y:z:yaw:t|move:id:x:y:z:yaw|kill:id|wipe")` →
  `ents <spawned> <moved> <killed> <errors> <ms>` (этап 5). Сущности моста — мобы — с тегами `MCW_ENT` и
  `MCW_E<id>` (id 0..63), без `MCW_BLOCK`: `mcw_count`, `mcw_countblocks`, `mcw_clearall` и `clear` в `mcw_batch`
  их не видят. Операции выполняются по порядку. `spawn` сначала сносит всё с тегом слота, `move` —
  `GetEntityByTag` + `TeleportWithRotation`, `kill` и `move` пустого слота — ошибка, `wipe` сносит все `MCW_ENT`.

У фейка есть режим старого мода, `FakeWitcher(legacy=True)` или `fake_w3.py --legacy`: без `mcw_countblocks`,
`mcw_boomat`, `mcw_ents` и без строки `normal`. Ещё открыто: токен сессии в `mcw_poll` из `@addField` modMCWProbe — ждёт спайка. С ним
загрузка сейва станет видна сразу, без сверки числа блоков.

В `mc\` блокирующих правок нет. `hello.world` мод только повторяет. Когда появятся измерения на мир Ведьмака,
мост будет слать в нём короткое имя мира (`novigrad`, `skellige`…, `bridge.world_name`).
