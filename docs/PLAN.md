# Minecraft × The Witcher 3: план

Цель: строишь и ломаешь блоки, крафтишь и встречаешь крипера посреди Велена. Логика блоков — настоящий Minecraft, а
показывает всё Ведьмак своими средствами: со своим светом, тенями, физикой и анимациями. С 2026-10-03 цель шире:
Стив вместо Геральта по схеме SkyCraft (этап 4, [STEVE.md](STEVE.md)).

Входная точка проекта — [DEVELOPMENT.md](DEVELOPMENT.md): запуск, управление, устройство, откат и «Что дальше» (актуальный
порядок работ). Этот файл — исходный план и решения.

Статус на 2026-10-03: без игры готово всё до этапа 2 включительно — набор спайка (`spike\`), сервер (`mc\`, смоук 33/33),
мост этапа 1 (`bridge\`, смоук 17/17 на фейке), логика этапов 3 и 5 (крафт до кирки, крипер; смоук 17/17), конвертер
текстур и `modMCWBlocks` на 11 блоков, собранный `wcc_lite` без

## Решение: Майнкрафт считает, Ведьмак показывает

```
Fabric-сервер 1.21.11                                  мост                                 Witcher 3 5.00c
headless, 127.0.0.1, мод MCW:                        (этап 1)                                -net -debugscripts, modMCW:
- мир блоков вокруг Геральта     ◄── TCP :25600 ──►     │   ── exec mcw_poll(seq) ──────►   - pos, cam, area, world,
- дроп, крафт, песок, вода, TNT      JSON-строки        │      10–20 Гц, TCP :37001           нажатия
- рельеф Ведьмака = barrier                             │   ◄── ответ на exec ───────────   - set/clear: CreateEntity,
- Геральт = ServerPlayer                                │      "[MCW#seq] …" … "end"          Destroy, тег MCW_BLOCK
  (схема Carpet), noPhysics                             │   ── exec mcw_batch(seq, ─────►   - mcw_boom, mcw_notify
- setBlock-миксин → blocks/тик                          │      "set:x:y:z:t|clear:x:y:z")
                                                        │   ◄┄┄ scriptslog.txt (запасной)   блоки = сущности Ведьмака:
                                                                                            cont_crate, с этапа 2 —
                                                                                            свои шаблоны из REDkit
```

Почему так, а не как в SkyCraft (там Майнкрафт сам водит игрока и рисует поверх): по каналу идут события и опрос
10–20 Гц, а не кадры; блоки как родные сущности сразу получают свет, тени, туман и коллизию, совмещать кадры по глубине
не нужно; как в CS2 × Gothic, камерой и движением управляет хост. Witcher Online гонял через exec позиции игроков и ушёл
на нативы из-за задержки, так что потолок у канала есть: его меряет спайк.

### Каналы
- **Ведьмак → мост: ответ на exec.** У глобальных exec-функций нет таймера, поэтому мост сам опрашивает `mcw_poll(seq)`
  10–20 раз в секунду. Каждая строка вывода — `Log("[MCW#<seq>] …")`, последняя — `[MCW#<seq>] end`: id запроса нет, и
  без маркера один потерянный ответ сдвигает всю очередь. Числа только целые: координаты в см, углы в сотых градуса,
  направления ×10000, время в мс (`FloatToString` может дать запятую). Ответ ≤32 767 байт. Запасной канал (асинхронные
  события, отладка) — хвост `scriptslog.txt` (`LogChannel('MCW', …)`, `-debugscripts`).
- **Мост → Ведьмак: exec**, как в консоли: `mcw_ping(17)`, `mcw_echo(3, "abc")`, `mcw_alias(4, 'barrel', 0.0)`. Блоки
  идут пакетом `mcw_batch(seq, "set:x:y:z:t|clear:x:y:z")`, разбор через `StrSplit`. Команда ≤32 767 байт (с мировыми
  см ~1 200–1 500 операций), поэтому `coords.py` режет пакеты по байтам; рабочий размер подбираем замером с 1–2 КБ.
  Экранирование, безопасный алфавит и разбор float-аргумента (точка или запятая) **[проверить]** charset-тестом. Сколько
  exec игра исполняет за кадр, **[проверить]**: если один, потолок ≈ FPS вызовов в секунду и выручают только пакеты.
- **Мост ↔ Fabric:** TCP с JSON-строками на `127.0.0.1:25600` (25599 занят примером GTA). Сокет читает поток-демон мода,
  с миром работаем через `server.execute()`, исходящие сливаем на `END_SERVER_TICK`. WebSocket примера GTA живёт в
  клиентском source set, на выделенном сервере его нет.
- **Агентский канал:** `spike\w3cmd.py` (аналог `gcmd.py`): exec любой команды, ok/fail, `--tail` для scriptslog,
  `--reload` для перекомпиляции. Консоль (`DBGConsoleOn=true`, `~`) через game-automation — только для отладки.

### Координаты
Ведьмак: метры, Z вверх. Майнкрафт: 1 блок = 1 м, Y вверх. `mc_pos = (w.x, w.z + Y_OFFSET, 1 − w.y)`, блок =
`floor(mc_pos)`; с `mc.z = −floor(w.y)` расходится только при целой `w.y`, поэтому блок считаем только через
`spike\coords.py`. Центр блока в мире Ведьмака — `(mc.x+0.5, −mc.z+0.5, mc.y−Y_OFFSET+0.5)` плюс поправка на pivot
шаблона (у cont_crate pivot в центре; таблица — `spike\templates.json`, код и тесты — `spike\coords.py`). Мир Ведьмака
узнаём по `GetCurrentArea()` (в 5.0 возвращает name) и `GetWorld().GetDepotPath()`. Вместо подбора Y_OFFSET под −64…319
рассматриваем свой `dimension_type` (min_y до −2032, высота до 4064) и измерение на каждый мир Ведьмака: novigrad,
skellige, kaer_morhen, bob, prolog **[проверить]**.

### Сторона Ведьмака (WitcherScript)
- Спавн: `(CEntityTemplate)LoadResource(path, true)` →
  `theGame.CreateEntity(tpl, pos, rot, , , true, PM_DontPersist, tags)`; тег `MCW_BLOCK` через `tags.PushBack` (литерала
  массива нет). Удаление — `Destroy()`. Мир хранит Fabric, после загрузки сейва блоки пересоздаёт мост.
- Состояние живёт только в полях объекта (`@addField(CR4Player)`). Индекс без map: мост сам раздаёт слоты, Ведьмак
  держит `array<CEntity>` и выполняет команды по номеру слота за O(1). `map<string,CEntity>` **[проверить]** в
  modMCWProbe. В спайке `mcw_batch` ищет блок по координатам перебором — годится только для замеров. Сброс полей после
  загрузки сейва **[проверить]**: мост сверяет токен сессии и при расхождении шлёт ресинк.
- Луч взгляда: `RayCastSync`/`StaticTraceWithAdditionalInfo` дают компонент → `GetEntity().HasTag('MCW_BLOCK')`.
- Ввод: в спайке — горячие клавиши моста, которые вызывают exec. С этапа 1 — `IK_*=(Action=MCW_Break)` в
  `input.settings` и `GetLastActivationTime` в `mcw_poll`, пункт меню — `user_config_matrix\pc\input.xml`.

### Сторона Майнкрафта (Fabric, `mc\`)
- Изменения блоков: один миксин на RETURN `Level.setBlock(BlockPos,BlockState,II)Z`. Копим позиции, на `END_SERVER_TICK`
  читаем итоговое состояние и сравниваем с зеркалом: через setBlock идут песок, вода, взрывы и ломка игроком. Загрузку
  чанков миксин не видит, поэтому снапшот отдаём при `hello` и по `ServerChunkEvents.CHUNK_LOAD`. Взрыв
  (`ServerExplosionMixin`) — только эффект, снесённое придёт в `blocks`.
- Геральт — настоящий `ServerPlayer` в `PlayerList` по схеме Carpet 1.4.194: `FakeClientConnection`, миксин `PlayerList`
  (listener с пустым send, подмена при respawn), ручной `loadPlayerData`, `noPhysics` (PlayerMixin из примера GTA),
  позиция через `absSnapTo` + `getChunkSource().move`. Fabric `FakePlayer` не годится: его нет в PlayerList, поэтому
  через 60 с сервер встаёт на паузу, а через 300 тиков замерзают сущности.
- Ломка — `handleBlockBreakAction` START/STOP (дальность, время копания, дроп по инструменту); установка — `useItemOn`,
  проверки дальности, высоты и `mayInteract` повторяем в моде. В `act` мост шлёт позу на момент действия.
- `server.properties`: `pause-when-empty-seconds=0`, `online-mode=false`, `server-ip=127.0.0.1`, void через `flat` +
  `the_void`. Время суток берём у Ведьмака (gamerule `advance_time false` + `time set`). Рельеф Ведьмака → barrier
  (`solid`/`clearSolid` из `WorldBridge` примера GTA), в события он не попадает.

### Ассеты (только из твоей установки, в мод не кладём)
- **Блоки:** свой `.w2ent` (CStaticMeshComponent, `isStreamed=false`) + `.w2mesh` куба 1 м + `.w2mi` на `pbr_std` +
  `.xbm`. Коллизию даёт второй невидимый компонент с ванильным `box.w2mesh`, его запись уже есть в `collision.cache`
  **[проверить]**. Текстуры — пикселями прямо в xbm или своим `texture.cache` через w3edit **[проверить]**, иначе кук
  REDkit. `.w2ent`/`.w2mi` делает только REDkit. Тип блока — отдельный `.w2ent` или appearance (`ApplyAppearance`).
- **Конвертер текстур** (без REDkit) берёт `versions\1.21.11\1.21.11.jar`: тинт по `tintindex` + `colormap\grass.png` и
  `foliage.png`, у анимационных полос (99 `.mcmeta`) первый кадр, атлас граней на тип (у grass_block, oak_log,
  crafting_table грани разные), nearest 16→256. MVP этапа 2: grass_block, dirt, stone, cobblestone, oak_log, oak_planks,
  sand, crafting_table и серый куб для неизвестных.
- **Стив:** как в Custom Player Characters — `Exclude/IncludeAppearanceTemplate` по частям тела на скелете Геральта
  (опора — открытый `nikich340/w3.NewPlayerCharacters`). **Крипер:** взрыв — ванильная бочка `barrel` → `SetOnFire`
  (эффект, урон, тряска камеры), снос блоков считает сервер.

## Критерии выхода из спайка
- exec отвечает на 5.0.0.1044392, и вывод Log() приходит в ответе (иначе см. запасные варианты);
- p95 RTT exec в открытом мире при 60 FPS < 150 мс;
- не меньше 20–30 exec в секунду при глубине 1 или `mcw_batch` на 100 операций за вызов;
- известны рабочая длина команды и ответа (≤32 767 байт) и безопасный алфавит;
- 100/1000/3000 cont_crate замерены (FPS, время кадра, время спавна, RAM), 1000 не роняют FPS заметно;
- modMCW компилируется, а по modMCWProbe понятно, есть ли состояние в `@addField`.

Бюджет считаем по неландшафтным блокам с открытой гранью. Предварительно **[проверить]**: радиус 32 м, до 2000
сущностей, тени дальше 32 м выключены, пул (`Teleport` + `SetHideInGame`) вместо частых `CreateEntity`/`Destroy`. Не
тянет — держим блоки в радиусе 30–50 м, остальное выгружаем.

## Запасные варианты
- **exec на 5.00c мёртв.** (1) Откат Steam-ветки на next-gen 4.04 (buildid 14504303) и REDkit next-gen: протокол там
  работал, но сейвы и ассеты 5.0 станут несовместимы. (2) Свой ASI с нативами для скриптов — реверс с нуля; образцы:
  открытый dinput8-прокси RefinedPT (5.0), закрытый Spawn Menu 2.0, рецепт Witcher Online (только 4.04). (3) Консоль и
  game-automation — только отладка, не транспорт.
- **Log() не приходит в ответе.** Обратный канал — хвост `scriptslog.txt` (`DebugScriptsForceFlush=true` уже стоит); RTT
  вырастет, критерий 150 мс может не выполниться.
- **modMCW не подхватился.** Тумблеры, cmdline, `-forcescriptcompilation`; частичный спайк — на ванильных exec.
- **@addField или map не компилируются.** Без состояния: теги, `GetEntitiesByTag` (O(N)), `SphereOverlapTest`, имя-тег
  блока аргументом `name` прямо из моста (по команде на блок), FactsDB для чисел.
- **Совсем без внешнего процесса.** Мир блоков в WitcherScript, сохранение в FactsDB, логику майна пишем заново.
- **Рука Стива в кадре.** Вид от первого лица — мод 13072 под 5.0 (идёт с ASI и dinput8), рука с киркой — `gpu_overlay`
  из CS2 × Gothic: захват окна от DX12 не зависит.

## Решения

**Принято**
- EULA Minecraft принята 2026-10-02. Сервер запускаем только на 127.0.0.1 и только в `mc\run\`.
- Сервер 1.21.11, а не 26.3: есть локальный клиент для отладки и текстур и JDK 21 — при Loom 1.17.x (26.3 и Loom 1.18.x
  требуют JVM 25).
- `cookedfinal.redscripts` не трогаем, ванильные `.ws` не копируем, правим только аннотациями.
- Геральт в Майнкрафте — ServerPlayer по схеме Carpet; порт мост ↔ Fabric — 25600.
- REDkit качается (≈60 ГБ загрузки, ≈111 ГБ на диске). Нужен с этапа 2 (для чего именно — см. «Что известно»), всё
  до этого делаем без него. Для справки, один раз: по EULA REDkit собранные в нём моды — только для The Witcher 3 («not
  with other games») и некоммерческие; loose `.ws` под неё не подпадают.

**Открыто**
- Правило брандмауэра Block для 37000/37001 (launch.md): 37001 слушает 0.0.0.0, у witcher3.exe правила Allow после
  запроса — вносишь ты, от администратора. (Exec на 5.00c жив, откат на 4.04 и свой ASI не нужны; разрешения на моды,
  порт и клавиши в окне игры даны 2026-10-03.)
- JDK 21: рантайм лаунчера Minecraft (может смениться при обновлении лаунчера) или отдельный Microsoft/Temurin.
- Этап 1: выживание или творческий режим. (Дроп — в мир с подбором, крипер — на ИИ Майнкрафта: так сделаны этапы 3/5,
  `bridge\smoke_stage35.py`.)
- Публикация: если будет, то Nexus или GitHub без игровых и майнкрафтовских файлов (mod.io не пропустит).
