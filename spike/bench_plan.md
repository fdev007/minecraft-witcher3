# Спайк: замеры канала exec (`-net -debugscripts`, порт 37001)

Инструменты рядом: `w3net.py` (клиент протокола), `w3cmd.py` (агентский канал), `bench_w3.py` (замеры),
`fake_w3.py` (фейковая игра по контракту modMCW). Каждый прогон `bench_w3.py` пишет JSON в `results/`
(`bench_<время>_game.json`, в `meta.label` — состояние игры). Итоговые числа переносим в `RESULTS.md` таблицей,
как в `cs2-gothic/spike/RESULTS.md`; каждый вылет записываем с временем и командой, после которой он случился.
Порядок шагов с игрой — `launch.md` (0a–0h); здесь — что мерить и как читать результат.

## 0. Перед игрой

1. Самопроверка без игры: `python -m pytest -q test_w3net.py` (132 теста) и `python bench_w3.py --fake all`.
   Числа фейка — только проверка формата: у него кадр 16,7 мс и все exec кадра обрабатываются разом.
2. Пользователь запускает игру с `--launcher-skip -net -debugscripts` (в первый раз с модом ещё
   `-forcescriptcompilation`), modMCW (и отдельно modMCWProbe) лежат в `mods\`, загружен сейв в открытом мире.
   `cookedfinal.redscripts` не трогаем.
3. Включён счётчик FPS (оверлей Steam, RTSS или PresentMon): бенч FPS не видит, его записываем руками.
4. Во время замеров окно игры в фокусе, если пункт не говорит иначе.

## 1. Связь и протокол (первые 10 минут, по порядку)

Каждая строка закрывает вопрос, который пока **[проверить]**. Шаги совпадают с `launch.md` 0c–0d.

| Шаг | Команда | Что записать |
|---|---|---|
| порт открыт | `netstat -ano \| findstr 37001` | слушает `127.0.0.1` или `0.0.0.0` (если `0.0.0.0` — закрыть 37001 входящим правилом брандмауэра) |
| моды, конфиг | `python w3cmd.py --info` | `modMCW` в списке модов; раздел `[Scripts]` конфига (`LogDebugScripts` и т.п.) |
| пакеты без запроса | `python w3cmd.py --listen 60` **до первого exec** (походить по миру, открыть меню) | шлёт ли игра что-то сама (строка `no-netlog` в exe); вид пакета |
| протокол жив | `python w3cmd.py "mcw_nope()"` | ожидаем `fail` с текстом `Warn: Failed to process command` (код 1 — это и есть успех шага): функции нет, побочных эффектов нет, ответ короткий, сейв не нужен. `TimeoutError` — повторить с `--bind-delay 1.0` (rw3d по умолчанию ждёт 500+750 мс после BIND); снова тишина — протокол молчит на 5.00c |
| ванильный exec | `python w3cmd.py --fifo "spawnbarrel()"` (`launch.md` 0c) | `ok` и `Spam: ...` одним пакетом, у ног Геральта бочка |
| exec мода | `python w3cmd.py "mcw_ping(#)"` | см. исходы ниже; `packets=` — один пакет на exec, пакет на строку или статус отдельно |
| Log и LogChannel | `python w3cmd.py --tail "mcw_logtest(#)"` | что пришло в ответе (`via Log`? `via LogChannel`?), что в `scriptslog.txt` (`[log] ...`) и с каким префиксом |
| перекомпиляция | `python w3cmd.py --reload` | работает ли на 5.0, время до `finished`, вид `warn`/`error`; пакеты ScriptCompiler незнакомой формы печатаются как `[reload] raw: ...` / `[unsolicited] ...` — переписать их целиком |
| без BIND | `python -c "import w3net; c=w3net.W3Client(namespaces=()).connect(); print(c.exec('mcw_ping(1)', timeout=2).text)"` | ответ или `TimeoutError` (rw3d говорит, что BIND обязателен) |
| два клиента | `w3cmd.py --listen 30` в одном окне, `w3cmd.py "mcw_ping(#)"` в другом | видит ли первый чужие ответы (тогда seq обязателен и для чужих клиентов) |
| экранирование | `python bench_w3.py charset` | печатает «безопасный алфавит» (`safe_alphabet`); `expected_fail` — `"` и `'`: на 5.00c кавычка внутри строки ломает разбор всей команды (замер 2026-10-03, ожидаемо, в `bad` не идёт); `bad_chars` (ответа нет вовсе) и `mangled` (ответ есть, строка испорчена) — неожиданное. Экранирования нет: `\` доходит как есть, `StrLen` считает байты UTF-8 (`aжb` → 4); пустую строку `""` игра не разбирает (`" "` — да). Фейк разбирает так же |

`logstats()` для первой проверки не годится: это тяжёлая ванильная команда, она пишет сотни строк
`LogChannel('Stats')` (`temp.ws:6184-6300`, `core\misc.ws:135`), включая каждый предмет инвентаря. Если LogChannel
попадает в ответ exec, ответ длиннее 1999 байт, а такой игра теряет целиком (замер 5.00c, п. 5) — ответа не будет.

Исходы `mcw_ping(#)`:
- `ok packets=1` — ответ одним пакетом, строки через `\n` (как предполагали rw3d и W3MP);
- `ok packets=2+` — пакет на каждую строку `Log()` и/или статус `Spam` отдельным пакетом до или после строк
  (rw3d PR #12: exec «streams its script log output»). Клиент собирает до `[MCW#n] end`; если `Spam` пришёл
  раньше строк, а маркеров ещё не было, он ждёт маркер `status_grace` = 0,25 с. На мост не влияет;
- `fail ... 'Spam' без маркера` — за 0,25 с после `Spam` строк не было: `Log()` не попадает в ответ. Канал
  «игра → мост» тогда только файл: `W3Client.attach_scriptslog()`, бенч с `--via-log`, задержку меряет `loglat`;
- `fail ... Failed to process command` — функции нет: мод не скомпилировался или не подключён (`--reload`, `--info`);
- `fail игра не слушает (... отказ ...)` — нет `-net`, не тот порт (37000 у игры из REDkit — клиент пробует его
  вторым) или брандмауэр. Отказ на localhost Windows отдаёт только через ~2 с, поэтому `connect_timeout` = 3 с;
- `TimeoutError` при живом `--info` — повторить с `--bind-delay 1.0`.

Если `--listen` показал exec-образные пакеты без запроса, ванильные команды без seq (FIFO) в мосте не используем
вовсе: такой пакет займёт место ответа FIFO-команды (на фейке с пакетом раз в 3 мс — около трети), а настоящий ответ
придёт позже и может достаться следующей команде. mcw-команды сопоставляются по seq: пакет без маркера к ещё не
начатой seq-команде не приписывается (на фейке 30 из 30 `mcw_poll` ok), к уже идущей прилипает только к `.lines`,
не к `.body`. После `TimeoutError` у FIFO-команды (её ответ мог опоздать) мосту надёжнее переподключиться:
опоздавший ответ seq-командам не достанется, но следующей FIFO-команде — может.

## 2. Основной прогон: открытый мир, 60 FPS

`python bench_w3.py all --label "мир 60fps"` (если `mcw_ping` дал «`Spam` без маркера» — с `--via-log`).
`all` = `rtt rate frame poll echo probe charset loglat batch stress`: лёгкое раньше, спавн в конце, чтобы вылет не
съел остальное. По умолчанию `batch` — 1, 10 и 50 операций (одна команда), `stress` — 100 и 1000; `batch 1000`
(~27 КБ, 15 команд по 2047 байт) и `stress 3000` — только отдельно, после сохранения (п. 4). `launch.md` 0e запускает тот же набор без `stress`.

У каждого теста есть `calls` и `bad` (Warn, «тихий» `Spam`, нет `end`, потерян, таймаут). Задержки и вызовы/с
считаются только по годным ответам; если первые 5 вызовов теста плохие, тест прерывается. Если в каком-то тесте
все ответы плохие, бенч пишет в stderr «ни одного годного ответа: …» и выходит с кодом 1 — числа такого теста не брать.

| Тест | Что меряет | На какой вопрос отвечает |
|---|---|---|
| `rtt` | 300 последовательных `mcw_ping`: p50/p95/p99; шаг `engineMs` между ответами | задержка туда-обратно; `engine_ms_delta_p50` ≈ время кадра → exec исполняется раз в кадр |
| `rate_depth_N` | вызовов/с при N запросах в полёте (1 = последовательно) | растёт ли пропускная способность с конвейером; `lost` > 0 = игра теряет ответы, `not_ok` — ответы без `pong` |
| `frame_burst_N` | N `mcw_ping` разом, сколько разных `engineMs` в ответах | сколько exec игра исполняет за кадр: вся очередь или по одному |
| `poll` | `mcw_poll`: задержка и размер ответа | цена опроса позиции и камеры |
| `echo_Nb` | `mcw_echo` с аргументом N байт туда и обратно (`--sizes`, по умолчанию 256, 512, 1024, 1900) | растёт ли задержка с размером. Ответ на 48 байт длиннее аргумента: с 1900 байт он 1948 — у предела 1999, клиент предупредит (`near_limit`). Размер, где команда длиннее 2047 или ответ длиннее 1999 байт, пропускается (`skipped`) |
| `probe` | `mcwp_state/put/get/del` | работают ли `@addField` с `map<string, CEntity>`. `available`: `false` — функции нет (проба не скомпилирована), `no_data_channel` — ответ `Spam` без маркера (нужен `--via-log`), `no_reply` — таймаут |
| `charset` | символы в строковом аргументе | алфавит для `mcw_batch` и `mcw_notify` |
| `loglat` | `mcw_logtest` → строки в `scriptslog.txt`: задержка `[MCW#n] end` (Log, `log_end`) и `via LogChannel` (`logchannel`) отдельно | задержка файлового канала (по строке `end` на нём завершает команды `--via-log`); что из Log/LogChannel попадает в ответ, а что в файл. Три промаха подряд — тест прерывается с `error` |
| `batch_N` | `mcw_batch` из N `set`, затем N `clear` (мировые см, 4 м перед Геральтом); больше ~74 операций — несколько команд не длиннее 2047 байт (`cmds`), `set`/`clear` — задержки отдельных команд | байт на операцию, время разбора и спавна в игре (`game_set_ms_p50`), операций/с |
| `stress_N` | `mcw_stress` 100/1000, держим `--hold` с, пингуем | время спавна, пинг и шаг `engineMs` с N блоками, `clearall` |

Размер пакета exec: **36 байт + длина команды в UTF-8**. Пределы exec на 5.00c (замер 2026-10-03,
`w3net.EXEC_MAX_CMD` / `EXEC_MAX_REPLY`): команда до **2047 байт** (от 2048 игра молча выбрасывает её — ответа нет,
соединение живо), ответ до **1999 байт** (длиннее теряется целиком, хотя функция отработала и её строки есть в
`scriptslog.txt`), строка `Log()` длиннее ~1999 символов приходит как `......(truncated).......`. Предел i16 у строки
протокола (32 767) на практике не достигается. Операция `set:1234500:-678900:1550:0|` в мировых сантиметрах — около
27 байт, значит в команду влезает около 74 операций (мост берёт `batch.bytes` = 1900, ~70). Вывод любой функции
держать короче 1999 байт: всё длиннее дробить на несколько вызовов.

## 3. Состояния игры

В каждом состоянии: `python bench_w3.py rtt frame --n 100 --reps 5 --label "<состояние>"`, затем
`python w3cmd.py "mcw_poll(#)"`, чтобы убедиться, что клиент жив после выхода из состояния.

| Состояние | Что записать |
|---|---|
| пауза (меню Esc), инвентарь, карта | отвечает ли exec; `engine_ms_delta` (идёт ли время движка) |
| окно без фокуса (Alt-Tab) | ответы и задержка; не засыпает ли игра |
| диалог, катсцена | отвечает ли exec; можно ли спавнить (`mcw_cube`) |
| экран загрузки (быстрое перемещение во время `rtt --n 300`) | теряются ответы (`bad`, `lost`, `TimeoutError`) или опаздывают (`stats.late` в `client` JSON) |
| главное меню (сейв не загружен) | что отвечает `mcw_poll` без `thePlayer` (не уронил ли игру); строки `pos` нет — `poll` здесь весь `bad`, это ожидаемо |
| ограничение FPS 30 / 60 / без ограничения | `rtt.p50` против времени кадра: `rtt ≈ k × кадр` значит исполнение на кадре игры |

Признак Nagle или отложенного ACK у игры: задержки «прилипают» к ~40 или ~200 мс. TCP_NODELAY у клиента включён.

## 4. Сущности (после сохранения)

`python bench_w3.py stress --levels 100,1000,3000 --hold 10 --label "стресс, Белый Сад"`,
отдельно `python bench_w3.py batch --ops 1000 --label "batch 1000"`.

- Перед этим сохранить игру. FPS записывать руками в середине каждого `hold`; RAM процесса — диспетчер задач.
- Отойти на 50–100 м: не пропадают ли блоки (стриминг), не пропадает ли коллизия.
- `engine_ms_delta_p50` под нагрузкой — грубый заменитель времени кадра, если оверлей FPS не работает.
- `game_spawn_ms` против `rtt_spawn_ms`: сколько стоит спавн внутри одного exec (один кадр или растянуто).

## 5. Пределы длины (последним, отдельно)

Замер 5.00c 2026-10-03: команда до 2047 байт, ответ до 1999 байт (п. 2, «Размер пакета exec»). `python bench_w3.py
maxlen` перепроверяет оба предела двоичным поиском с seq из 10 цифр; команды длиннее 2047 байт шлёт мимо проверки
клиента (`W3Client.max_cmd`):
- предел команды — `mcw_batch(seq, "x…x")`: одна нераспознанная операция, ответ `batch 0 0 1 <ms>` короткий при
  любой длине команды. Длина команды от 64 до `--hi` (по умолчанию 4096) байт → `cmd_max_ok`, `cmd_first_bad`;
- предел ответа — `mcw_echo(seq, "x"*n)` в пределах найденной длины команды; ответ на 48 байт длиннее аргумента →
  `reply_max_ok`, `reply_first_bad` (байт ответа), `echo_max_ok_arg`; `reply_first_bad_outcome`: `lost` — ответа
  нет, `truncated` — пришёл `......(truncated).......`;
- `long_line` — что пришло на самую длинную `mcw_echo`, влезающую в команду (строка `Log()` длиннее 1999 символов):
  ожидается `truncated`.

Выброшенная команда и потерянный ответ выглядят одинаково — ответа нет, поэтому проба ждёт не дольше 1 с (`--timeout`,
если он меньше), а найденные границы в конце перепроверяются с обычным таймаутом: `stable = false` — короткий таймаут
принял заминку игры за потерю, прогон повторить. `cmd_match` / `reply_match` — совпали ли пределы с константами
`w3net`; не совпали — поправить `EXEC_MAX_CMD` / `EXEC_MAX_REPLY` и `coords.MAX_CMD`. `fatal_at` — соединение
пропало: это вылет, записать длину и время. С `--via-log` предел ответа не мерится (строки приходят из файла
целиком), поэтому maxlen — без него. На фейке: 2047 / 2048, 1999 / 2000 `lost`, `long_line` = `truncated`.

## 6. Надёжность

- Перезапуск игры при работающем мосте: срабатывает `W3Client.on_disconnect`, ожидания получают `ConnectionError`,
  любой новый запрос — тоже `ConnectionError` сразу (не таймаут); переподключение — новым `connect()` раз в 2 с.
- Загрузка другого сейва: `python w3cmd.py "mcwp_state(#)"` до и после. Токен должен смениться, поля опустеть
  (`@wrapMethod OnSpawned`); если не сменился — `thePlayer` не пересоздаётся, индекс блоков переживает загрузку.
- exec во время экрана загрузки: ответ, задержка или тишина (п. 3).
- `client.stats` в JSON: `late` (опоздавшие ответы), `stray_status` (лишние `Spam`), `silent` (ответы без маркера),
  `salvaged` (пакет с битой длиной выброшен, разбор продолжен), `unsolicited`, `near_limit` (ответ от 1799 байт —
  90 % предела), `truncated` (строки ответа, которые игра заменила на `......(truncated).......`).

## Выход из спайка

Числа берём только из тестов с `bad = 0` (или явно объясняем каждый `bad`, например загрузку в п. 3).

| Критерий (PLAN.md) | Откуда берём | Порог |
|---|---|---|
| ≥ 20–30 exec/с **или** пакеты по 100 команд | `rate_depth_1.calls_per_s`, лучший `rate_depth_N`; `batch_100` (две команды `mcw_batch`: в одну 2047 байт влезает ~74 операции) | ≥ 20 вызовов/с при `bad = 0`, либо `batch_100.bad = 0` и `set.p95_ms` < 150 (на команду) |
| задержка туда-обратно < 150 мс | `rtt.p95_ms`, мир, 60 FPS, `rtt.bad = 0` | < 150 мс |
| канал «игра → мост» есть | `mcw_ping` ok (Log в ответе) **или** `loglat.log_end.p95_ms` при `loglat.missing_end = 0` | ответ exec, либо файл с p95 < 150 мс |
| 1000 сущностей не роняют FPS заметно | `stress_1000` + FPS руками | падение FPS не больше ~10 % от исходного |
| состояние между вызовами | `probe.ok`; токен после загрузки сейва | `ok = true` |

Если не проходит:
- протокол молчит на 5.00c (`mcw_nope()` без ответа и с `--bind-delay 1.0`) — запасные пути из `PLAN.md`
  («Протокол отладки не работает на 5.0»);
- exec/с мало, а пакеты проходят — мост шлёт только `mcw_batch`, по одному на кадр;
- `Log()` не в ответе, файл медленный — опрос реже, события копятся в игре и отдаются пачкой;
- 1000 сущностей роняют FPS — блоки только в радиусе 30–50 м (как в `PLAN.md`), замерить, сколько тянет;
- `probe` не скомпилировался — индекс по тегам и `GetEntitiesByTag` (дорого, O(N)), см. условие 4 у критика.
